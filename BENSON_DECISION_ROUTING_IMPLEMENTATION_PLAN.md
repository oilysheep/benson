## 1. Objective, boundaries, and definition of done

Implement the approved architecture with one global **Benson Agent Completion Protocol**, automatically enforced on every Benson-managed agent run: Main, Jessica, Reminder, scheduled semantic runs, and future agents. `benson_complete` is a conceptual terminal primitive, not an asserted installed OpenClaw API or an approved new public tool.

The target flow is:

```text
Native admission -> Request Controller -> bounded Decision evidence / policy
  -> one committed Main or direct-domain execution owner
  -> native agent loop -> deterministic tools / authoritative evidence
  -> final semantic owner composition
  -> benson_complete -> schema and trusted-evidence validation
       rejected -> same-run completion-only repair; execution disabled
       exhausted / unable to finish -> trusted evidence sufficient: RECOVERED
                                      otherwise canonical FAILED report
  -> accepted protocol completion -> Completion Control
       CALLER -> Main workflow continuation / aggregation / final composition
                 -> Main benson_complete -> accepted final-workflow completion
       RESPONSE_CONTROLLER -> lossless direct final-workflow projection
  -> Response Controller: trusted finality, eligibility, bounds, one finalization
       usable userResponse -> already-final message
       explicit unavailable in valid completion -> one-shot bounded fallback
  -> final approved message -> prepare -> freeze -> existing native queue
  -> sendPrepared/provider outcome or native durable recovery
```

TaskResultEnvelope and ResponseEnvelope are roles/kinds within one versioned family. Completion outcome is runtime-assigned: NORMAL means benson_complete accepted an agent-authored completion; RECOVERED means exhausted attempts were replaced by a complete trustworthy runtime-constructed completion grounded in sufficient trusted evidence; FAILED means runtime cannot establish such a completion. These outcomes are separate from task/workflow status: RECOVERED preserves actual success, failure or partial outcome, and envelope-generation failure must not downgrade verified execution success. FAILED uses a schema-valid evidence-preserving report of the completion gap, not a fabricated complete task result. Schema validity alone does not justify RECOVERED; every required semantic claim and binding must be grounded. Explicit unavailable userResponse remains a valid protocol state and alone does not imply FAILED. Completion acceptance, execution outcome, physical completion, workflow finality, queue custody, and delivery are distinct. Structured domain facts remain authoritative; model-authored identity, route, authorization, provenance, verification, or delivery policy never grants trust. A domain child finalizes its run without acquiring its parent's final-response authority.

Main retains context-dependent reasoning, broad reasoning, delegation, dependencies, aggregation, and final wording for its workflows. Direct routing remains a self-contained-request optimization. Domain owners compose direct responses, preferably with local deterministic templates for known verified shapes. Response Controller does not normally render results or semantically review arbitrary prose. A second LLM must not review the first LLM's arbitrary prose.

Done means the revised stages, architecture coverage in Section 8, mandatory acceptance scenarios, and isolated negative matrix have observed evidence. Real direct routing cannot be accepted with only an unavailable Decision provider. Positive conditional execution cannot be accepted with only synthetic completion or negative no-reminder tests. A limited rollout is explicitly limited; it does not close this whole plan.

Out of scope: unrelated domain expansion, a Reminder Python-to-JS service migration, heartbeat investigation, checkpoint-retention cleanup, new agent frameworks, message buses, MCP/A2A, duplicate stores/queues/dispatchers, and general model-fallback redesign. Jessica exact physical-completion capability remains owned by [its existing capability plan](agents/jessica-vacuum/FULL_CAPABILITY_PLAN.md). No new persistent surface, public tool, service, registration, or architectural boundary is approved merely by naming a logical component here.
