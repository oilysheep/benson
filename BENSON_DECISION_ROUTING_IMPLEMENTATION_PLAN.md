## 1. Objective, scope and approval boundary

Replace the General Workflow design with authenticated input admission, independent Agent Run settlement, durable domain operation ownership and native event/schedule/delivery mechanisms. Remove prospective JOIN/CLOSE, membership revisions, shared finals, retained orphaned lifecycle state and a global dependency/capacity engine. Preserve Main's bounded semantic coordination, strict completion validation, evidence-based recovery and proven domain safety.

The target is a Deterministic-First, Domain-Owned, Event-Driven Agentic System under Architecture §§1/4/8.1/9. Generic admission routes direct, Main-delegated, event and Automation tasks to one logical owning-domain entry; adequate structured intent requires deterministic handling, and only necessary reasoning requests a fresh authorized domain Run. Main remains the central cognitive orchestrator and sole user-facing agent without a mandatory model hop. Request disposition, Run outcome, physical outcome and delivery outcome remain distinct. A finished Run is never resumed to await a device. Durable Event-Triggered Conditional Actions remain explicitly deferred and visible as a release limitation.

### 4.3 Native binding decisions and alternatives

Architecture §27.2 contains the current primary sources and decision rationale. Apply them to exact installed bindings:

- Prefer shared `registerService` lifecycle over Jessica-specific watchers. Prove startup/stop/reconnect/backpressure and source filtering; no model event polling.
- Prefer deterministic domain reconciliation; use `runtime.subagent.run` only where fresh reasoning is necessary and trusted tool authority is proven. `deliver:false`, an idempotency option or a plugin owner marker does not supply a human principal. `runContext` is transient. Current-requester dispatch closures cannot be captured and reused after their authorized callback.
- Reject official-install-only `gateway.request` / `dispatchHookAgentTurn` as a local authorization workaround. Inspected provenance values include `external_user`, `inter_session`, `internal_system`; do not invent `system_event` support.
- Native `enqueueSystemEvent` is an in-memory, coalescing existing-session mechanism, not a durable fresh event-to-Run authorization contract. `waitForRun` timeout does not cancel work.
- Prefer supported universal terminal lifecycle control. Accepted P01 source evidence at PR #18 commit `681ea91e59c8bee753093dee9c77208799f1c4fd`, this Plan's historical §6.4 row G01/O08, records the 2026-10-03 audit of installed `docs/plugins/hooks/prompt-and-session.md:271–301` and `dist/hooks-CKanWLsK.mjs:525–584`: `before_agent_finalize` can request revision of natural finals, excludes user abort, has a 15-second budget/default fail-open policy, and can be overridden by force-finalize; `agent_end` is observational.
